# 报告契约与完成门槛

在输出最终审计结果前读取本文件。报告按候选问题聚合，不按代理逐份倾倒。严重度与裁决词汇沿用 `SKILL.md` 定义；本文件只定义报告层级、门禁映射和完成条件。

## 1. 默认报告

按以下顺序输出存在实际内容的部分：

1. **门禁结论**：`READY`、`READY-WITH-CONDITIONS`、`BLOCKED` 或 `INCOMPLETE`，附一句证据化理由。
2. **范围与基线**：工件、不可变 refs、审计模式、要求、关键假设和排除项。
3. **已确认问题**：按严重度和用户影响排序。
4. **决策项与条件项**：分别列出 `NEEDS-DECISION` 和 `CONDITIONAL`。
5. **验证与残留缺口**：关键检查、独立覆盖、未验证平台/交互和容量降级。
6. **已验证正确**：只列最高风险且有直接证据的行为。

不存在内容的章节省略。不要为了填满模板输出空标题、重复检查清单或代理过程。

## 2. 每个候选问题的字段

每个确认问题包含：位置和归因；严重度与证据等级；预期行为及其依据；原因→实际影响路径；触发条件或可重复步骤；主代理验证方式；根因模式、确认/排除实例及 `ISOLATED/SYSTEMIC/UNKNOWN` 范围裁决；建议修复和可判定通过条件。只在必要时引用最小代码片段，不回显秘密或不必要的可滥用细节。

## 3. 追溯模式

以下情况默认展开追溯附录：用户明确要求逐代理记录或完整证据账本；发布/合并门禁存在争议；Critical/High 候选存在冲突证据；关键材料、环境或独立覆盖缺失（门禁为 `INCOMPLETE`）。

附录包含：覆盖矩阵（`代理 | 证据轴 | 主责 | 范围 | 重叠不变量 | 实际检查`）；候选账本（来源、主代理复核、最终裁决、模式范围）；会改变结论的重大 `REJECTED` 项及反证；与门禁直接相关的命令、环境和基线失败。普通报告内部仍保留这些记录，但不默认倾倒完整代理原文。

## 4. 门禁映射

| 条件 | 门禁结论 |
|---|---|
| 存在已确认、现实可达且与发布相关的 Critical/High | `BLOCKED` |
| 关键证据、目标环境或独立覆盖缺失，无法可靠判断是否存在阻断项 | `INCOMPLETE` |
| 没有已确认阻断项，但发布前仍有明确、可验证的非阻断前置条件 | `READY-WITH-CONDITIONS` |
| 完成门槛满足，且没有阻断项或未完成条件 | `READY` |

`CONDITIONAL`、`NEEDS-DECISION` 是候选裁决，不直接等于门禁；按它们是否造成关键判断缺口映射到 `INCOMPLETE` 或 `READY-WITH-CONDITIONS`，不得覆盖已确认的阻断缺陷。

## 5. 阻断与解除条件

每个 `BLOCKED` 项必须有：

```text
[ ] <需要完成的动作>
    退出条件：<可观察、可测试、可判定的通过条件>
```

影响仍属推断时不要阻断，裁决为 `CONDITIONAL` 或 `NEEDS-DECISION`。缺陷已确认但尚无具体修复方案时仍可阻断，解除动作写为"确定、实施并验证修复方案"，退出条件写为"原触发路径不再失败且相称回归通过"。报告文字本身不是通过门禁。

## 6. 无确认问题的措辞

独立覆盖和关键检查达标时：

> 在已审计范围和已执行检查内未发现已确认缺陷。

未完成独立交叉验证时：

> 已完成的单代理或部分审查未发现候选问题，但未完成独立交叉验证，不能视为全面无缺陷结论。

绝不声称"绝对安全""没有 bug"或"所有场景均正确"。

## 7. 完成清单

- [ ] 每个有实际影响的候选问题都有严重度、归因、主代理复核和最终裁决。
- [ ] 所有 Critical/High 已获得两个独立视角，或明确记录无法交叉验证的缺口。
- [ ] 已确认候选问题有触发条件、证据、模式范围、修复建议和通过条件。
- [ ] 每个阻断项都有解除动作；无证据的推断没有升级为阻断。
- [ ] 运行时或平台主张有真实公共路径或对应版本契约，或保留 `CONDITIONAL`。
- [ ] 临时证据包、探针和隔离环境已清理；只读审计没有修改项目。
