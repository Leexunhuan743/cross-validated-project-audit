# 跨项目高价值失败模式

**按需读取**：需要补充 Hypothesis seeds、做系统性模式搜索，或初始风险地图存在明显盲区时读本文件。

每条都是 **Hypothesis seed，不自动成为 Finding**。命中后必须回到当前工件取 DIRECT Evidence，并主动寻找反证与安全反例。

格式：`触发信号 / 寻找反证 / 最小验证 / 应关闭该 Hypothesis`

## 模式清单

**测试没有判别力** — 新测试在恢复旧实现、撤掉 guard 或切换成功/失败路径后仍会通过 / 测试是否真正到达目标分支，是否断言了错误类型、状态或副作用 / 在 PRE-fix 版本运行，或在隔离副本做最小变异 / 测试只是明确标注的 smoke test，且目标行为由其他判别性测试覆盖。

**测试镜像实现而非生产路径** — 测试 helper 重写生产算法、mock 绕过真实边界、只测解析副本 / 是否还有测试调用公共入口或核心生产路径并覆盖相同不变量 / 从用户或调用方入口追踪实际调用链，比较测试触达路径 / 纯函数已被生产和测试共同调用，helper 没有复制逻辑。

**失败分支被吞掉** — 宽泛异常捕获、只断言"不崩溃"、失败时跳过断言、错误被替换为成功默认值 / 调用者是否明确将该错误视为可忽略，且保留了可观测状态 / 强制进入失败分支，核对返回值、状态、日志和副作用 / 错误被有意降级且契约、指标和恢复行为一致。

**测试或兼容代码保活旧风险** — 新实现替代旧 helper/writer/route/export，但旧路径仍被测试、feature flag 或调用者引用 / 旧路径是否已安全封装、只存在于不可交付的历史夹具，或有明确兼容期限 / 搜索符号、exports、路由、注册表、feature/test-only 构建和最终包内容 / 旧入口仍受支持且行为与新入口同样安全。

**新校验卡死旧数据** — 迁移、rename 或修复路径先用新规则校验历史值，旧记录永远无法处理 / 是否存在旧值豁免、归一化、显式迁移或兼容读取 / 用代表性旧记录走真实迁移或修改入口 / 产品明确拒绝旧数据且提供了可执行迁移/清理门禁。

**全量写回造成丢失更新** — 从旧快照执行整行/整对象写回，覆盖并发产生的单调或独立字段 / 事务隔离、版本条件、锁或字段级更新是否阻止覆盖 / 画出读写时间线，构造两次交错更新并检查最终状态 / 数据所有权是单写者，且此约束由代码或存储层强制。

**多边界操作留下半成品** — 文件先写、metadata 后写，多表或外部/本地操作缺少事务、补偿或恢复标记 / 是否有原子 rename、事务、幂等补偿、启动恢复或不可见暂存区 / 在每个 I/O 边界注入失败，检查公开内容、临时状态、索引和重试 / 中间状态不可见、可自动恢复且契约允许短暂不一致。

**重试缺乏幂等性** — 部分成功后整批重试会重复消息、扣款、版本推进、写入或资源创建 / 幂等键、完成前缀、去重存储、事务边界或精确重试分类是否存在 / 让第一次调用在最后一个边界失败，再用同一输入重试 / 操作契约明确是 at-least-once，且消费者安全去重。

**关停或等待无界** — `wait`、`receive`、`join`、握手或 `drain` 没有 timeout、取消或失败传播 / 上层是否施加硬截止时间，资源是否保证终止 / 阻塞生产处理函数，检查能否在有界时间退出并释放资源 / 进程级契约允许永久服务，且该等待不在用户可触发的关停路径。

**新入口激活潜伏缺陷** — 新路由、导出、UI 入口或 feature flag 接通旧代码，使既有缺陷首次可达 / 旧代码是否只在受控条件下调用，或新入口增加了完整保护层 / 从新入口沿调用链检查权限、状态、序列化、时区和错误路径 / 潜伏缺陷仍不可达，且不可达性由稳定约束保证。

**实现存在但未接线，或旧路径仍占主导** — 新代码未导出、未注册、未加入路由/构建；调用者仍绕过它使用旧行为 / 是否由自动发现、代码生成或运行时注册可靠接线 / 检查入口、exports、注册表、feature flag、生成物和最终包 / 代码是明确未启用的后续阶段，且本次需求不声称可用。

**文档或计划过度承诺** — 把条件性、进程内或特定平台行为写成绝对保证 / 生产路径、测试或权威契约是否支持完整主张 / 为每个用户可见主张建立"主张 → 实现 → 测试/证据"映射 / 措辞明确限定条件、版本、平台和已知例外。

**交付树与意图不一致** — 缺 lockfile、workspace 成员、vendor marker、生成物、export、文档、测试或配置；或混入无关文件 / 项目策略是否自动生成或明确排除这些文件 / 对照需求、commit set、name-status、构建配置和最终产物逐项核对 / 缺失项由发布流程可靠生成，且该流程和输入已验证。
