# 真实用户路径与运行时验证

只在候选问题涉及用户可见行为、公共 API/CLI、迁移、平台语义、并发交错或第三方运行时时读取本文件。目标是验证真实入口，而不是为积累通过结果而运行更多测试。

## 1. 选择公共入口

| 工件 | 优先入口 | 关键观察 |
|---|---|---|
| CLI | 实际命令、参数组合和批量调用 | 退出码、stdout/stderr、错误文本、状态变化 |
| API/服务 | 公共 endpoint、SDK 或协议请求 | 鉴权上下文、响应、错误、重试、副作用 |
| UI | 用户可见页面和控件 | gating、导航、取消/重入、持久状态、键盘/a11y |
| 数据/迁移 | 真实旧数据形状和迁移入口 | 兼容读取、部分失败、恢复、重试、回滚 |
| 库/SDK | 公开 export 和典型调用方 | 签名、默认值、异常、版本与安装产物 |
| 并发/生命周期 | 生产调度、取消、关停和资源边界 | 交错、超时、释放、重复调用、背压 |

优先使用用户或调用方真正能触达的入口。测试 helper、内部函数和 mock 只能支持局部主张，不能替代公共路径。

## 2. 记录验证档案

对每个运行时 finding 保留：

```text
入口：<命令、endpoint、UI 路径、公共函数或迁移入口>
环境：<OS、版本、构建模式、依赖版本>
前置状态：<数据、配置、身份、文件系统状态>
操作/命令：<可重复步骤；敏感值用占位符>
预期：<来自需求、契约或既有兼容行为>
实际：<可观察输出、状态或副作用>
重复性：<稳定、交错依赖、偶发、未能重复>
清理：<已删除的临时资源和未触碰的真实系统>
```

不要回显秘密、真实用户数据、私钥、令牌或敏感 URL。复现细节只保留证明问题所需的最小信息。

## 3. 安全执行顺序

1. 静态追踪入口、调用链、保护条件和可能影响。
2. 复用仓库已有、已检查且与候选项直接相关的测试或工具。
3. 调用最小公共路径，并限制输入、时间、资源和网络范围。
4. 需要修改状态时使用仓库外隔离副本、临时 worktree、临时数据库或可丢弃环境。
5. 需要安装工具、下载依赖、扩大网络、使用凭据、付费资源、外部写入或生产访问时暂停并请求授权。
6. 无法获得目标平台时，查阅对应版本的官方契约。只有契约明确覆盖完整调用链、版本、配置和触发条件时，才可确认纯契约主张；仍依赖目标状态或集成语义时保留 `CONDITIONAL`。
7. 清理探针、临时文件、进程、容器和测试数据，再复核原工作区状态。

不要为了前向验证直接执行未检查的 lifecycle、build、install、hook 或测试脚本。先读取脚本和配置，识别下载、任意代码执行、秘密访问和外部副作用。

## 4. 按风险构造最小场景

### 正常路径

- 先确认最基本的用户工作流能完成。
- 核对输出与需求，而不只检查进程是否退出或页面是否渲染。

### 常见变化

- 覆盖用户自然会尝试的空值、边界值、重复调用、不同顺序或批量输入。
- 不生成需要多个罕见前提的理论场景，除非影响是 Critical 且前提真实存在。

### 错误与取消

- 覆盖缺失输入、明显非法输入、依赖失败、取消、超时和部分完成。
- 检查原始错误是否保留、资源是否释放、状态是否可安全重试。

### 旧数据与旧调用方

- 使用代表性旧 schema、配置、序列化值或调用签名。
- 验证兼容读取、迁移、fallback 和明确的不兼容门禁。

### 并发与生命周期

- 构造最小交错，而不是依赖大量随机循环碰运气。
- 明确同步点、预期不变量和超时上限。
- 无法稳定复现时记录交错假设和环境限制，不把偶发信号当确认事实。

## 5. 证据判定

- **CONFIRMED**：真实公共路径或对应版本权威契约证明候选主张，影响和触发条件均现实可达。
- **CONDITIONAL**：静态路径可信但缺少目标平台、版本、状态或可重复运行证据。
- **REJECTED**：保护条件、安全反例、不可达约束或真实运行结果否定候选主张。
- **NEEDS-DECISION**：行为本身可证实，但是否接受属于产品、范围或兼容策略取舍。

代理报告、日志片段、测试通过或一次偶发失败都不是单独确认依据。

## 6. 与独立代理分工

- 让静态审查者识别候选路径和不变量。
- 让用户路径审查者从公开入口验证预期与实际，不向其泄露静态审查者的预期结论。
- 让主代理检查两者是否真正使用不同证据；相同代码推断不能冒充两份独立证明。
- 需要写探针或测试时，由主代理批准隔离位置和清理方式；发现阶段子代理不得修改用户项目。

## 7. 无法验证时的报告

说明：

1. 已完成的静态追踪和支持证据。
2. 缺失的目标环境、版本、凭据或外部条件。
3. 能区分真假的最小后续验证。
4. 未验证是否影响门禁；关键缺口映射为 `INCOMPLETE`，非阻断前置条件可映射为 `READY-WITH-CONDITIONS`。

不得用“看起来应该”“两个代理都认为”或其他平台模拟替代缺失证据。
